# WALL-E GPU 服务部署说明

部署时间：2026-11-27。GPU 服务器为云平台提供的 Ubuntu 容器，运行 Supervisor，GPU 为 Tesla V100S 32 GB。

## 接口和进程

- 管理页面：`https://zhanhui.cloud/walle/`
- AI 服务：`https://zhanhui.cloud/walle/ai`
- 状态接口：`GET /health`；状态中的 `dialogue_ready` 和 `tts_ready` 会在首次推理加载模型后变为 true。
- 对话：`POST /chat/send`、`POST /chat/stream`、`POST /input`。
- 语音识别：`POST /stt`，表单字段 `audio_file`。
- 活体：`POST /face/liveness`，表单字段 `image`。接口要求恰好一张正面人脸；该模型未经真人与照片对照验收，不应用作安全身份认证。
- AI 接口除 `/health` 外要求管理后端签发的 JWT（`token` 请求头）或机器人令牌（`X-Walle-Device-Token`）；普通用户仅能访问获准的本人数据和功能。
- GPU 容器内 AI API 的 `6006` 和 TTS 的 `6007` 监听 `0.0.0.0`，优云智算外网防火墙已放行这两个 TCP 端口。2026-11-27 已从外网验证两个 `/health` 返回 200，未授权访问业务接口返回 401。两个服务的 `/health` 可公开访问，其余接口需要管理员 JWT 或设备令牌。AI 进程会使用设备令牌访问 TTS。
- 两个服务的直接端口使用明文 HTTP，可能暴露认证令牌、文本和音频；远程访问优先通过现有 HTTPS 入口。
- VPS 上 `walle-gpu-tunnel.service` 连接 GPU 主机的 `6006`；Nginx 将 `/walle/ai/` 转发至隧道。`walle-voice-bridge.service` 转发后台音色参考音频和合成请求。

管理员和设备令牌在本机 `WALL-E-服务器访问信息.env`；GPU 服务器 `/workspace/walle-ai/.env` 和 VPS `/opt/walle-server/.env` 也有对应密钥，禁止提交至 Git。

## 模型与数据

- 对话模型：Qwen2.5-14B-Instruct，4-bit 量化，V100 使用 FP16 计算。源码中的 `well_E_dpo` 适配器基于 1.5B 模型，未挂载到 14B 模型。
- 识别：SenseVoiceSmall；合成：GPT-SoVITS v2，默认音色使用系统生成的中文参考语音。其他音色需要合法参考音频及相应文字。
- 情感分类与活体检测加载项目已有权重；用户记忆、人设、生成音频存储在 GPU 服务器 `/workspace/walle-ai/TransformerAItalk/data/`。
- GPU 服务器的数据和模型不包含在原 VPS 的 MySQL 自动备份中。云实例重建、停机后存储是否保留需以云厂商规则为准，应另行备份用户记忆、人设、参考音频及部署目录。
- 音色档案原始音频存放在 VPS 的 `walle-server_voice_data` 卷。GPT-SoVITS 通过私有桥接读取后上传到 GPU，未在公网暴露音色桥接服务。

## 运行维护

GPU 容器内：

```sh
supervisorctl status walle-ai walle-tts
supervisorctl restart walle-ai
supervisorctl restart walle-tts
tail -f /workspace/walle-ai/ai.log
tail -f /workspace/walle-ai/tts.log
```

VPS：

```sh
systemctl status walle-gpu-tunnel walle-voice-bridge
curl -fsS https://zhanhui.cloud/walle/ai/health
```

两台服务器之间用受限 SSH 密钥建立隧道；GPU 容器内的 Supervisor 对进程异常执行自动重启。云平台容器重建后的配置持久性尚未验证。

本地部署副本为 `WALL-E-GPU-deploy`。仓库内 TURN 地址排序及 ICE 响应的 `Cache-Control: no-store` 调整尚未部署到 GPU 服务；线上现有 TURN 配置已通过仅中继视频帧测试。机器人实机麦克风、音频播放器和远程控制需要另行接入与验收。
