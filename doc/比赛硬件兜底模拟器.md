# 比赛硬件兜底模拟器使用说明

## 目标

比赛现场如果真实硬件临时出问题，先不要改 Web 和后端代码，直接在电脑上启动 `hardware-demo` 里的模拟模块，保证演示能继续。

当前模拟器覆盖四类风险：

| 硬件问题 | 启动方案 | 能演示什么 |
| --- | --- | --- |
| 摄像头坏、树莓派摄像头被占用 | `socket-camera` | 后端收到机器人在线，Web 端能拿到模拟画面，遥控指令能到模拟机器人 |
| WebRTC 视频通话无法接入树莓派 | `webrtc-video` | 模拟树莓派接听 Web 远程监护通话并发送演示画面 |
| 星闪/雷达体征模块坏 | `health` | 健康监测页有心率、呼吸、温度、湿度、跌倒数据 |
| 事件提醒演示缺硬件播报 | `events` | 模拟机器人从后端同步提醒，到点打印提醒内容 |
| 后端还走机器人 IP 拉流 | `local-camera` | 电脑临时提供 `/video_feed`，把设备 IP 改成电脑 IP 即可 |

## 目录

```text
hardware-demo/
  hardware_demo/          Python 模拟器源码
  scripts/                Windows PowerShell 一键脚本
  tests/                  标准库 unittest 测试
  requirements.txt        运行依赖
  README.md               简短命令说明
```

## 赛前准备

在 Windows 服务器电脑上进入项目根目录：

```powershell
cd D:\你的项目目录\WALL-E\hardware-demo
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

如果 PowerShell 不允许执行脚本，管理员打开 PowerShell 后执行一次：

```powershell
Set-ExecutionPolicy RemoteSigned
```

## 必须对齐的配置

默认设备号是 `WALLE_1`。Web 的设备列表中，默认设备的设备号也应该是 `WALLE_1`。

如果比赛时使用 FRP 域名访问，把环境变量设置成当前域名：

```powershell
$env:WALLE_PUBLIC_SERVER_URL="https://你的FRP新域名"
$env:WALLE_API_BASE_URL="$env:WALLE_PUBLIC_SERVER_URL/api"
$env:WALLE_SOCKETIO_SERVER_URL="$env:WALLE_PUBLIC_SERVER_URL"
```

如果只在 Windows 本机测试：

```powershell
$env:WALLE_PUBLIC_SERVER_URL="http://127.0.0.1:8088"
$env:WALLE_API_BASE_URL="http://127.0.0.1:8088/api"
$env:WALLE_SOCKETIO_SERVER_URL="http://127.0.0.1:8088"
```

管理员后台建议确认：

- `api.base-url`：公网演示时填 `https://你的FRP新域名/api`
- `socket.server-url`：公网演示时填 `https://你的FRP新域名`
- `robot.http-port`：本地 HTTP 摄像头兜底时保持 `5000`
- `robot.default-ip`：新建设备默认机器人 IP，不影响已存在设备

## 方案 A：摄像头坏了

优先使用 Socket.IO 摄像头模拟：

```powershell
cd D:\你的项目目录\WALL-E\hardware-demo
.\scripts\run_socket_camera.ps1
```

它会：

- 连接 `WALLE_SOCKETIO_SERVER_URL`
- 加入房间 `robot_WALLE_1`
- 持续发送 `camera_frame`
- 打印 Web 下发的 `cmd_motor`、`cmd_servo`、`cmd_animate`、`cmd_settings`

判断是否成功：

- 后端控制台能看到 Socket.IO 连接
- 模拟器控制台显示 `joined room: robot_WALLE_1`
- Web 遥控时，模拟器控制台能打印电机/舵机等指令

## 方案 A2：WebRTC 视频通话兜底

如果比赛时要演示的是 Web 左侧菜单里的“远程监护 / 视频通话”页面，而真实树莓派不能接听通话，启动：

```powershell
cd D:\你的项目目录\WALL-E\hardware-demo
.\scripts\run_webrtc_video.ps1
```

这个脚本会安装额外依赖 `aiortc/av/numpy`，然后模拟树莓派接入房间 `0001`。Web 页面点击“加入房间”“请求监视”后，模拟器会自动回复 Answer 并发送演示视频流。

判断是否成功：

- 模拟器显示 `joined room: 0001`
- Web 页面日志出现远端视频流
- 远端视频区域出现 `WALL-E WEBRTC DEMO` 演示画面

注意：WebRTC 依赖安装比普通模拟慢，建议赛前在 Windows 电脑提前跑一次 `run_webrtc_video.ps1`，不要等比赛现场临时装。

## 方案 B：体征数据硬件坏了

正常体征：

```powershell
cd D:\你的项目目录\WALL-E\hardware-demo
.\scripts\run_health.ps1
```

异常体征或跌倒演示：

```powershell
.\.venv\Scripts\python.exe -m hardware_demo.cli health --mode abnormal
.\.venv\Scripts\python.exe -m hardware_demo.cli health --mode fall
```

判断是否成功：

- 模拟器控制台每隔几秒打印 `hr/br/temp/hum/fall`
- Web 或小程序健康监测页面能看到数据刷新

## 方案 C：事件提醒演示

先保证账号里已经创建了事件提醒，然后启动：

```powershell
$env:WALLE_DEMO_USERNAME="admin"
$env:WALLE_DEMO_PASSWORD="admin123"
.\.venv\Scripts\python.exe -m hardware_demo.cli events
```

到点后控制台会打印：

```text
[event] reminder triggered: 事件名 - 提醒内容
```

## 方案 D：电脑临时模拟机器人 IP 摄像头

如果当前 Web 控制台仍然通过后端 `/api/robot/video-feed/{machineId}` 去拉机器人 HTTP 视频流，可以启动本地 MJPEG 摄像头：

```powershell
.\.venv\Scripts\python.exe -m hardware_demo.cli local-camera --port 5000
```

然后在 Web 的设备列表里，把对应设备的机器人 IP 改成 Windows 电脑的局域网 IP，例如 `192.168.1.20`。后端会访问：

```text
http://192.168.1.20:5000/video_feed
```

## 一键全部启动

```powershell
cd D:\你的项目目录\WALL-E\hardware-demo
.\scripts\run_all.ps1
```

这个会同时启动：

- Socket.IO 摄像头模拟
- 体征数据上传
- 事件提醒轮询

## 比赛现场建议流程

1. 先启动 Windows 上的 MySQL、后端、Nginx、FRP。
2. 浏览器打开 FRP 域名，确认能登录。
3. 管理员后台确认 `api.base-url` 和 `socket.server-url` 是当前 FRP 域名。
4. 普通账号进入设备列表，确认默认设备号为 `WALLE_1`。
5. 真实硬件正常时，用真实硬件。
6. 真实硬件摄像头异常时，开 `run_socket_camera.ps1`。
7. 体征硬件异常时，开 `run_health.ps1`。
8. 多个硬件都不稳定时，开 `run_all.ps1`。

## 注意事项

- 模拟器是兜底方案，不要在真实硬件正常时同时开同一个 `WALLE_1` 模拟器，否则同一设备会出现两路数据。
- 如果比赛现场换了 FRP 域名，只改环境变量和管理员后台配置，不要改代码。
- 如果要模拟第二台设备，设置 `$env:WALLE_DEVICE_NAME="WALLE_2"`，并在 Web 设备列表添加设备号 `WALLE_2`。
