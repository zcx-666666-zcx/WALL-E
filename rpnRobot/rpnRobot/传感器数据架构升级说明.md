# 传感器数据存储架构升级说明

## 架构变更概述

本次升级将原有的单一传感器数据表结构调整为**分表存储**架构，每个传感器类型独立存储，更好地支持单个传感器数据变化时的独立处理。

## 新的数据库表结构

### 1. 分表设计（5个独立表）
- `sensor_fall` - 跌倒传感器数据表
- `sensor_temperature` - 温度传感器数据表  
- `sensor_humidity` - 湿度传感器数据表
- `sensor_rate` - 心率传感器数据表
- `sensor_breathe` - 呼吸频率传感器数据表

### 2. 表结构特点
每个表都包含以下核心字段：
- `id` - 主键自增ID
- `device_id` - 设备标识
- `timestamp` - 数据时间戳
- `message_id` - OneNET消息ID
- 传感器特有字段（如fall、temperature等）

## 代码架构变更

### 1. 实体类更新
新增5个专门的实体类：
- `SensorFall.java`
- `SensorTemperature.java` 
- `SensorHumidity.java`
- `SensorRate.java`
- `SensorBreathe.java`

### 2. Mapper层重构
每个传感器类型都有对应的Mapper接口：
- `SensorFallMapper.java`
- `SensorTemperatureMapper.java`
- `SensorHumidityMapper.java`
- `SensorRateMapper.java`
- `SensorBreatheMapper.java`

### 3. Service层增强
- 保留原有`SensorDataService`接口兼容性
- 新增各传感器专用Service接口和实现类
- `SensorDataServiceImpl`重构为路由分发逻辑

### 4. 控制器扩展
新增`SensorDataController`提供RESTful API：
- `/sensor/latest` - 获取所有传感器最新数据
- `/sensor/history/{deviceId}` - 获取历史数据
- `/sensor/{sensorType}/latest` - 获取特定传感器最新数据

## 数据处理流程

### OneNET数据接收流程
1. `OneNetCallbackController`接收POST数据
2. 签名校验通过后保存原始消息到`device_message`表
3. 调用`SensorDataServiceImpl.parseAndSaveFromOneNetMessage()`解析数据
4. 根据`ds_id`字段识别传感器类型
5. 将数据保存到对应的专用表中

### 示例数据处理
```json
{
  "dev_name": "WALEE_1",
  "at": 1772104873379,
  "pid": "kCx33ym0Dt",
  "type": 1,
  "ds_id": "temperature",
  "value": "36.1"
}
```
此数据会被解析并保存到`sensor_temperature`表中。

## 部署步骤

### 1. 数据库迁移
执行`database/sensor_data_tables.sql`脚本创建新表

### 2. 代码编译部署
```bash
mvn clean install
```

### 3. 应用重启
重启Spring Boot应用使新配置生效

## API使用示例

### 获取所有传感器最新数据
```bash
GET /sensor/latest
```

### 获取特定设备历史数据
```bash
GET /sensor/history/WALEE_1?startTime=1772104873000&endTime=1772104874000
```

### 获取特定传感器最新数据
```bash
GET /sensor/temperature/latest
```

## 优势特性

1. **独立存储** - 每个传感器数据独立存储，互不影响
2. **灵活扩展** - 易于添加新的传感器类型
3. **高效查询** - 针对特定传感器的查询性能更优
4. **数据完整性** - 避免了NULL值填充问题
5. **向后兼容** - 保留原有接口，平滑过渡

## 注意事项

1. 原有的`sensor_data`表仍然存在但不再使用
2. 如需查询聚合数据，可使用提供的视图或自定义查询
3. 建议定期清理历史数据以维护性能
