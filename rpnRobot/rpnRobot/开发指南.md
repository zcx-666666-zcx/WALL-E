在使用推送服务时，DMP作为客户端，而用户的第三方应用是作为服务器，第三方应用需要支持URL验证以及数据接收两部分服务，可将数据推送给应用服务。

1. HTTP推送参数设置
   展开菜单栏中的「 数据流转」，点击「 数据推送」，进入HTTP推送列表页面。列表展示所有产品信息，您可为具体某产品设置HTTP推送参数

参数说明
参数	说明
推送地址	应用服务器处理请求的URL地址，需要同时支持GET和POST两种方式。平台通过GET请求对应用服务地址有效性进行验证，通过POST请求将数据推送至应用服务器
Token	应用服务器通过授权Token对平台身份进行校验，保证数据传输安全
消息加密方式	支持明文模式和安全模式，安全模式采用AES加密算法，可支持自定义或系统随机生成16位长度的加密密钥
2. URL验证
   配置了HTTP全局推送参数后，点击完成，系统将自动进行URL验证。
   URL验证流程如下图所示：
   image

DMP会向填写URL地址发送HTTP GET 请求进行URL验证，请求形式示例如下：

http(s)://url?msg=xxx&nonce=xxx&signature=xxx
其中，url为用户在页面配置时填写的URL，nonce、msg、signature用于URL及token的验证

携带参数信息包括：

参数	说明
msg	推送的消息内容。实例验证阶段，为平台生成的随机字符串；接收消息阶段，为平台推送的设备或业务消息数据
nonce	平台生成的随机字符串
signature	加密签名，signature结合了创建实例填写的token参数和请求中的msg、nonce参数
应用服务器收到请求后，需要通过signature参数字段对请求进行校验。若确认此次GET请求来自DMP，需在响应中原样返回msg参数，实例验证才能通过，否则验证失败，实例配置不生效。signature参数校验方法如下：

(1) 将实例配置时填写的token参数及校验请求中携带的nonce、msg参数拼接得到字符串A，即A = token + nonce + msg
(2) 将字符串A进行md5加密得到字符串B
(3) 将字符串B进行Base64转换，并通过URL Decode计算后得到参数C，将参数C与signature进行对比，相等则表示校验成功，标识请求来于DMP
如果token验证成功，返回msg参数值，表示URL验证通过。
如果用户不想验证token，可以选择跳过MD5计算过程，直接返回msg参数值

3. 数据通用推送
   目前平台支持设备生命周期、设备物模型、场景联动触发日志等数据推送。推送数据以JSON形式置于HTTP请求中的body部分，推送消息格式如下：

{
"msg": "XXXXXXXXXXX", # 消息内容，JSON字符串
"signature": "message signature", # 加密签名
"nonce": "7nJL0dGt" # 随机字符串
"time":  1725962719211,  # 消息推送时间
"id":  "9841f9ca7c094c71a1dede953a082e65"  # 消息id
}
参数	类型	说明
msg	string	消息内容
nonce	string	用于计算签名字符的随机串
signature	string	加密签名，用以校验推送客户端身份合法性，校验方法见实例验证
time	long	推送时间戳（毫秒）
id	string	消息id
详细消息类型推送格式可参考数据格式

4. 加密传输
   用户在配置推送服务时，可配置为数据加密传输，DMP支持AES对称加密（加密方式采用AES的CBC模式，数据填充采用PKCS7），用户可通过页面配置密钥，并在应用端通过该密钥进行解密操作（详情见最佳实践示例）。

示例：密文格式
{
"msg": "XXXXXXXXXXX", # 消息内容，JSON字符串
"signature": "message signature", # 加密签名
"nonce": "7nJL0dGt" # 随机字符串
"time":  1725962719211,  # 消息推送时间
"id":  "9841f9ca7c094c71a1dede953a082e65"  # 消息id
}

参数	类型	说明
msg	string	消息内容
nonce	string	用于计算签名字符的随机串
signature	string	加密签名，用以校验推送客户端身份合法性，校验方法见实例验证
time	long	推送时间戳（毫秒）

5. 数据接收
   平台以HTTP POST请求形式向第三方平台URL地址推送数据，第三方平台接收到数据后需要返回HTTP 200，否则DMP会认为此次推送无效并重试。

注意：第三方平台接收到DMP推送的数据后，建议先将数据加入到本地缓存队列，直接返回HTTP 200，后续再进行数据解析处理。
6. 重推策略
   应用服务器收到平台每一次推送请求后，需要在有限时间内返回响应（目前是3秒），且HTTP响应状态码应设置为200，否则平台会认为请求发送失败，进行消息重推。重推采用指数退避策略，具体如下：

第几次重试	与上次间隔时间	第几次重试	与上次间隔时间
1	1秒	10	6分钟
2	5秒	11	7分钟
3	10秒	12	8分钟
4	30秒	13	9分钟
6	2分钟	15	20分钟
7	3分钟	16	30分钟
8	4分钟	17	1小时
9	5分钟
7. 告警策略
   以下情况将给用户发送关停前的告警提醒短信：

连续失败推送次数达到500次，且距离上次发送告警短信时间间隔达到5分钟以上时，则发送告警短信，未满足任何一个条件都不会发送告警短信;
超时推送次数达到500次/小时，且距离上次发送告警短信时间间隔达到5分钟以上时，则发送告警短信，未满足任何一个条件都不会发生告警短信。
8. 关停策略
   以下情况将关停推送，并给用户发送推送已关停告知短信：

当连续失败次数少于1000次，但推送失败时间超过24小时，发送关停短信并关停该推送。
当连续失败次数达到1000次，且推送失败时间超过1小时，发送关停短信并关停该推送。
当连续失败次数达到2000次，发送关停短信并关停该推送。
当超时推送次数达到1000次/小时，发送关停短信并关停该推送。
9. 服务实现建议
   数据重复处理：DMP为了保证数据不丢失，有重发机制，如果重复数据对业务有影响， 数据接收端可以根据消息id对重复数据进行排除重复处理。

数据缓存处理：DMP每一次POST数据请求后，等待客户端的响应都设有时限（目前是3秒），在规定时限内没有收到响应会认为发送失败，累计失败1000次则会认为第三方服务不可用，服务将停止，所以建议第三方应用接收程序接收到数据时，先做数据缓存，再做业务逻辑处理。

IP白名单：为保证您在使用DMP的数据推送服务时，能够体验连续、稳定的服务，请将下述DMP数据推送的出口IP地址网段添加至您应用的IP白名单中：

183.230.40.0/24	183.230.102.0/24	218.201.45.0/25
10. 最佳实践
    JAVA代码示例

/**
* 功能描述: 检查接收数据的信息摘要是否正确。
* 方法非线程安全。
*
* @param obj     接受消息体对象 包含 msg nonce signature字段
* @param token   DMP配置页面token的值
* @return
*/
public static boolean checkSignature(BodyObj obj, String token) {
//计算接受到的消息的摘要
//token长度 + 8B随机字符串长度 + 消息长度
byte[] signature = new byte[token.length() + 8 + obj.getMsg().toString().length()];
System.arraycopy(token.getBytes(), 0, signature, 0, token.length());
System.arraycopy(obj.getNonce().getBytes(), 0, signature, token.length(), 8);
System.arraycopy(obj.getMsg().toString().getBytes(), 0, signature, token.length() + 8, obj.getMsg().toString().length());
String calSig = Base64.getEncoder().encodeToString(mdInst.digest(signature));
logger.info("check signature: result:{}  receive sig:{},calculate sig: {}", calSig.equals(obj.getSignature()), obj.getSignature(), calSig);
return calSig.equals(obj.getMsgSignature());
}
/**
* 功能描述：加密传输新消息解密
*
* @param msgOrigin       消息内容
* @param encodeKey       DMP中第三方平台配置页面生成的AES的BASE64编码格式秘钥
* @return                解密后的消息
*/
public static String decryptNewMsg(String msgOrigin, String encodeKey) throws NoSuchPaddingException, NoSuchAlgorithmException, InvalidAlgorithmParameterException, InvalidKeyException, IllegalBlockSizeException, BadPaddingException {
SecretKey secretKey = new SecretKeySpec(encodeKey.getBytes(), "AES");
//算法/模式/补码方式
//CBC模式 向量必须是16个字节
Cipher cipher = Cipher.getInstance("AES/CBC/PKCS7Padding");
cipher.init(Cipher.DECRYPT_MODE, secretKey, new IvParameterSpec(encodeKey.getBytes()));
byte[] data = cipher.doFinal(Base64.getDecoder().decode(msgOrigin));
return new String(data);
}
